:::::::::::::::::::::::::::::::::::::: questions

- What practices can ensure that a code assistant AI tool is used properly in
  research code development?

::::::::::::::::::::::::::::::::::::::::::::::::

::::::::::::::::::::::::::::::::::::: objectives

- Apply good practices to mitigate ethical, security, and skills-related risks when using AI in research.
- Develop personal or team-level guidelines for using a code assistant AI tool.

::::::::::::::::::::::::::::::::::::::::::::::::

In the previous episode, we learned about the general issues and potential risks
of using AI tools in developing codes in research. Here, we learn about a few
practices that are particularly important for reproducibility, provenance,
licensing, research integrity, and data protection:

1. AI platforms differ in how they handle submitted code and data. Check and
   configure the AI tool before use:
    - Check the terms of use, privacy settings, and code/data handling policies
    of the AI platform.
    - Ensure that your use of the tool is consistent with your institution's,
    funder's, and research project's requirements.
    - Where relevant, check whether your content (prompts and code) are used by the provider for
    model training.
    - Keep in mind that not using your content for training does not necessarily
    mean that the platform does not store it. **Never** share sensitive and private information.
    - Where relevant, check whether the "memory" feature of the AI tool is
    enabled and how it is set up to avoid the risk of cross-project
    contamination. Note that some platforms provide settings that separate
    personal memory from project-specific memory.

2. AI-generated code can contain bugs, incorrect assumptions, insecure
   practices, or scientifically inappropriate implementations. Treat
   AI-generated code as a draft:
    - Review, understand, test, and validate every generated code before using it.
    - Do not assume that code is correct simply because it looks plausible or
    runs successfully. Use unit tests and integration tests where appropriate.
    See this [Carpentries testing
    tutorial](https://carpentries-incubator.github.io/good-practices-lesson/4-testing.html).
    - Check scientific assumptions, algorithms, numerical methods, edge cases,
    and error handling. Do not rely solely on tests generated by the same AI
    assistant that generated the code.
    - Have a colleague review important or complex code where appropriate. In a
    team, use collaborative code review practices like pull requests and pair
    programming, see [Code Reviewing Process explained in The Turing
    Way](https://book.the-turing-way.org/reproducible-research/reviewing/)
    - Avoid relying on AI-generated "magic numbers" or parameter choices without
    understanding their justification and ask the tool to explain why, and
    verify against literature where relevant.

3. Researchers need to be able to explain and defend the methods implemented in
   their research software. Understand the generated code before incorporating
   it:
    - In your prompt, ask the AI tool to explain the proposed approach before generating the code.
    - Use prompts that encourage understanding rather than blind code generation.
    For example, instead of asking: “Write the complete implementation.”
    consider asking: “Explain three possible approaches and their trade-offs.”
    - Simpler and established implementations are generally easier to understand and validate.
    - Prefer established algorithms and well-maintained libraries where appropriate.
    - Check that external libraries and dependencies are appropriate and record
    their versions in a file (e.g., requirements.txt, or environment.yml) so
    results remain reproducible.

4. Automated checks provide an additional layer of protection:
    - Use automated software-quality tools like linting, formatting, static
    analysis, type checking, and security scanning tools. For example, see
    [Code quality explained in The Turing
    Way](https://book.the-turing-way.org/reproducible-research/code-quality/).
    - Use version control, such as Git, to track changes. See [Carpentries lesson
    on Version Control with Git](https://swcarpentry.github.io/git-novice/)
    - Run your normal Continuous Integration/testing pipeline on AI generated
    code. See [Carpentries lesson on Continuous
    Integration](https://carpentries-incubator.github.io/good-practices-lesson/5-ci.html#introducing-continuous-integration).

5. AI-generated code can resemble existing open-source code, while its
   provenance may not be obvious. This is not fundamentally different from a
   researcher finding and reusing code online, but AI can make the source less
   apparent:
    - Pay attention to copyright and software licenses. Read more about software
    license
    [here](https://esciencecenter-digital-skills.github.io/research-software-support/modules/licenses/info).
    - When AI-generated code appears unusually specific or closely resembles
    existing code, investigate its provenance before incorporating it.
    - Do not assume that modifying code removes the obligations associated with its original license.
    - Preserve required copyright notices, attribution, or other license requirements.
    - When the provenance or licensing status of a substantial piece of generated
    code is unclear, consider replacing it with an independently implemented
    solution or seek institutional/legal advice.

6. AI assistance can become part of the research process. Documenting it makes
   the development process more transparent and potentially easier to reproduce.
    - Record which AI tool/model was used, where practical. For example, you can
        use [AI Declaration Format](https://ai-declaration.org/).

7. Prompting Strategy:
    - Continuously refine prompts and instructions to improve output quality.
    - Regenerate code with a different prompt, or a different AI tool entirely,
    to cross-check for consistent results, especially for non-trivial logic
    e.g., statistical computations, numerical algorithms.
    - In prompts, ask for ideas, trade-offs, or pseudocode rather than complete
    solutions, especially for the core scientific logic of your project.

8. Use the right AI models and tools for your needs:
    - Large AI models offer advanced capabilities. However, they also consume
    significantly more computational resources, leading to higher CO2
    emissions. To minimize environmental impact, consider using smaller models
    for simpler tasks.
    - The use of tools (i.e conversational tools, IDE-integrated assistants, or
    autonomous agents) depends on specific development tasks, your
    preferences, and project constraints.
